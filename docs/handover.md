# 申し送り事項

納品時にお伝えする内容と、確認をお願いしたい事項をまとめたものです。
`docs/decisions.md` に分散している未確定事項・残課題を一本化しています。

---

## 1. ご判断をお願いしたいこと

### 1-1. 返品・キャンセル行（マイナス売上）の扱い

**現状: 有効な行として取り込み、合計から差し引いています。**

ECの実データには返品行が含まれます。これを弾きますと既存Excelと数字が合わなくなるため、
一致を優先する設定にしております（`docs/decisions.md` D-3 #3）。

ご確認いただきたいのは次の点です。

- 既存のExcelでは、返品行をどのように扱われていますか
- 返品を除外した「総売上」と、差し引いた「純売上」のどちらを
  KPIとしてご覧になりたいですか

**除外する運用をご希望の場合は設定を変更いたします。** 実装は軽微です。
検収での数値突き合わせの前にお決めいただけますと、手戻りがございません。

### 1-2. リピート率の定義

**現状: 定義の異なる2つを、それぞれ定義文つきで表示しています。**

| 表示場所 | 定義 | サンプルでの値 |
|---|---|---|
| KPIカード・月次推移 | その月に購入した顧客のうち、それ以前の月にも購入がある割合 | 9月 0.0% / 10月 38.5% / 11月 46.7% |
| リピート率（期間累計） | 期間内で2ヶ月以上購入した顧客の割合 | 28.6% |

2つある理由は、**この指標が月ごとの点を作れないため**です。
「複数月にわたって購入されたお客様の割合」（提案書 第7項）は複数月をまたいで
初めて判定できる数字で、そのままでは前月比つきのKPIカードにできません。
月次に落とすには定義の読み替えが必要になり、読み替えた数字は28.6%とは別物になります。

**既存Excelと突き合わせる際は、どちらの定義で計算されているかをご確認ください。**
片方に統一するご希望があれば、その方針に合わせます
（`docs/decisions.md` D-1）。

### 1-3. 保守契約の要否

納品日から30日間は不具合の修正を無償で対応いたします。
31日目以降は次からお選びいただけます。

- スポット対応（発生時にお見積もり）
- 月額保守 20,000円（税込）

**30日間の無償期間で実際に運用いただき、31日目にご判断いただくことを
おすすめしております。** 判断材料は `docs/roi-report.md` 第9項に記載しております。

どちらもお選びにならない場合も、ダッシュボードは引き続きご利用いただけます。
日次アクセスと外部監視も動き続けますので、**異常が起きたことは
保守契約の有無に関わらずお分かりいただけます。**

**ただし、通知が届くことと復旧作業がすぐ始まることは別です。**

| | 監視・通知 | 復旧の一次対応 |
|---|---|---|
| 納品から30日間 | 動きます | **行います** |
| 月額保守をご契約 | 動きます | **行います** |
| 保守をご契約されない | 動きます | **お見積もりのご承認後** |

31日目以降に保守をご契約されない場合、障害の通知は届きますが、
こちらから自動的に復旧作業を始めることはございません。
**この点をご理解いただいたうえでご判断ください。**
対応の詳細な手順は README の「運用手順（インシデント対応）」に記載しております。

## 2. 運用でご注意いただきたいこと

### 2-1. 毎月のCSVには過去の月も含める

**画面に表示されるのは、最後にアップロードしたCSV1件分だけです。**
当月分のみをアップロードされますと、前月比と月次推移が表示されなくなります。
詳細は `docs/operation-manual.md` 第3項。

### 2-2. Excel で保存し直す場合は「CSV UTF-8 (コンマ区切り)」

「CSV(コンマ区切り)」は Shift_JIS で保存されます。
現在は読み取れない行をスキップして理由を表示しますので数字が狂うことはありませんが、
**その行は集計に含まれません。** 詳細は `docs/csv-format.md` 第1項。

---

## 2-4. 実案件では、ROIの数字をヒアリングで確定させる

本レポート（`docs/roi-report.md`）は、実売上が不明なため仮定を置いた概算です。
実案件では次の順にヒアリングし、**仮定を実数に置き換えてから提出します。**

| 聞くこと | 何に使うか |
|---|---|
| 1. 実際の月間粗利額 | 規模別の表のどの行かが確定する |
| 2. 粗利率が悪化したときの平均的な変動幅 | 「2.1%」の仮定を実数に置き換える |
| 3. 現在その変化に何日後・何ヶ月後に気づいているか | 早期発見で短縮できる期間が出る |
| 4. 早期発見でどの程度損失を防げる見込みか | 「半分を取り戻す」の仮定を実数に置き換える |

**1つでも欠けると、回収期間は仮定のままになります。**
本レポートで仮定を明示する形にしたのは、この4つが未確定のためです。

## 3. 実案件として運用される場合に必要な移行

本システムは学習用の模擬案件として構築しております。
実際の商用運用に移される際は、次の3点の移行が必要です。

| 項目 | 現在 | 移行後 | 理由 |
|---|---|---|---|
| Vercel | Hobby（無料） | **Pro（月20ドル）** | Hobby は個人・非商用利用に限られる |
| メール送信元 | 開発者個人のドメイン | **貴社のドメイン** | 送信実績のあるドメインのほうが迷惑メールに入りにくい |
| 各アカウント | 開発者名義 | **貴社名義** | 提案書 第10項 |

**提案書と ROI分析レポートは Vercel Pro（月額実費3,900円）を前提に計上しております。**
移行によって費用が増えることはございません（`docs/decisions.md` D-13）。

## 4. 未実施の項目

正直にお伝えいたします。

各項目に「誰が・いつ・何を・完了条件」を明記しております。

### 4-1. 本番と同じ件数のデータでの検証

| | |
|---|---|
| **誰が** | 貴社ご担当者様（データのご提供）→ 開発者（検証の実施） |
| **いつ** | 着手から7営業日目まで（提案書 第7項）。検収の前 |
| **何を** | 本番と同じ件数の売上CSVをご提供いただき、画面の数値と既存Excelを突き合わせる |
| **完了条件** | 売上・粗利・リピート率が既存Excelと一致し、結果を書面でご報告した時点 |

提案書 第9項(1)は「サンプル40件だけでなく、本番と同じ件数のデータでも
一致すること」を検収基準としております。

**現時点で確認できているのは次までです。**

- サンプル40件での正解値との一致
- 2,500行を実際のDBへ保存し、読み出した結果が保存前と1円も違わないこと
  （`pnpm test:integration`）

**この点は特に重要とお考えください。** 少ない件数で数字が合っていても、
件数が増えると崩れることがございます。

ご用意が難しい場合は、こちらで同じ件数のテストデータを生成して測定し、
その旨を検収時にご報告いたします（提案書 第7項）。

### 4-2. AIコメントの人手判定（検収基準(2)(3)）

| | |
|---|---|
| **誰が** | 貴社ご担当者様と開発者が同席して判定 |
| **いつ** | 納品時の検収の場（提案書 第11項 12〜13日目） |
| **何を** | 貴社の実データでコメントを5本生成し、1本ずつ事実との整合と具体性を確認する |
| **完了条件** | (2) 事実と矛盾しないものが5本中4本以上、(3) 検討に値する具体性が5本中3本以上 |

同一データでの予行演習では、事実誤認ゼロ・アクション提案5本中5本が
具体性を満たすという結果でした（合格ラインは4本・3本）。

**ただしこれは予行演習であり、検収の代替にはなりません。**

### 4-3. 認証メールの日本語化（パスワード再設定以外）

| | |
|---|---|
| **誰が** | 開発者 |
| **いつ** | 招待機能をお使いになる運用へ変更されると決まった時点 |
| **何を** | Supabase の招待メールとメールアドレス変更確認メールのテンプレートを日本語化する |
| **完了条件** | 実際に送信し、日本語で受信トレイに届くことを確認した時点 |


パスワード再設定のメールは日本語のテンプレートに差し替え済みです。
**招待メールとメールアドレス変更の確認メールは、既定の英語のままです。**

現在は公開サインアップを無効にし、アカウントは管理者が作成する運用のため、
読み手7名様が受け取るのはパスワード再設定のみです。
**招待機能をお使いになる運用へ変更される場合は、同様の日本語化が必要になります**
（`docs/decisions.md` D-19）。

### 4-4. 障害通知の宛先へのご担当者様の追加

| | |
|---|---|
| **誰が** | 貴社（アドレスのご指定）→ 開発者（UptimeRobot への登録） |
| **いつ** | 納品時まで |
| **何を** | ご担当者様1〜2名様分のアドレスを監視サービスの通知先に登録する |
| **完了条件** | テスト通知を送り、ご指定の宛先の受信トレイに届くことを確認した時点 |

**現在の通知先は開発者のアドレスのみです。**

提案書 第6項(2)は「ご担当者様と弊社の両方へメールが送信されます」と
しております。

障害通知が届くまでの実測は約6分、復旧通知は約1〜2分です。
この実測は開発者宛で行っておりますので、ご登録後に改めて
到達をご確認いただきます。

ご登録後は、担当者様の異動・退職の際に宛先の変更をご依頼ください。
届かない状態のまま放置されますと、障害に気づけません。

## 5. Phase 2 でご提案が可能なもの

提案書 第2項でお伝えした、今回のスコープ外の機能です。

- Shopify API 直接連携（日次で自動更新。CSVを扱う工程がなくなります）
- 異常検知アラート（前月比±20%で Slack へ通知）
- PDFレポートの自動生成とメール配信
- Amazon・楽天など多店舗対応
- 日次・週次での表示

このうち **Shopify 連携と異常検知アラートの2つ**が、
`docs/roi-report.md` で整理した投資回収に最も効きます。
前者はアップロードのし忘れを構造的に防ぎ、後者は変化の検知を
月1回から翌朝へ早めるためです。

## 6. 保守を引き継がれる方へ

セキュリティ上、変更してはいけない設定を README の
「**変更してはいけない設定**」にまとめております。

- Supabase の公開サインアップを有効に戻さないこと
- `NEXT_PUBLIC_` の付け外しをしないこと
- Vercel の Git 連携を切ったままにすること

いずれも、変更するとエラーを出さずに壊れます。
保守をご担当される方へお渡しください。
